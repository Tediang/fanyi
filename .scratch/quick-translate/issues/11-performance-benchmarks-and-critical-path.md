# 11 — 建立性能基准并优化关键路径

**What to build:** 为快译的本地启动与请求路径建立可重复性能基准，并优化到界面出现和请求发出目标；供应商延迟与 App 自身延迟可以被独立观察。

**Blocked by:** 04 — 打通选词翻译与分享翻译; 05 — 打通 Moto AI 键快捷键翻译; 10 — 完成限制、失败恢复与脱敏诊断.

**Status:** ready-for-agent

- [ ] 分别记录触发到界面可见、触发到请求发出、请求到首个有效译文片段及总完成耗时。
- [ ] 使用确定性的本地假服务建立冷启动和暖启动基准，避免把互联网波动算作 App 回归。
- [ ] 目标设备上触发到紧凑界面可见的 P95 不超过 150ms。
- [ ] 已有有效配置时，触发到网络请求发出的 P95 不超过 300ms。
- [ ] 收到首个有效译文片段后立即渲染，不等待完整响应。
- [ ] 基准覆盖至少普通启动、选词入口和快捷键入口，并能比较修改前后结果。
- [ ] 性能优化不通过预读剪贴板、后台常驻、保存翻译内容或扩大权限实现。
- [ ] 性能结果和测试条件形成可复查记录，模拟器结果明确标为诊断数据而非真机验收。
