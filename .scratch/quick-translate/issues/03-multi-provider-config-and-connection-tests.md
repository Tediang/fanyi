# 03 — 完成多供应商配置与连接测试

**What to build:** 用户可以安全地保存、编辑、删除和切换多个命名供应商配置，并在发送真实翻译前测试连接。云端 HTTPS 服务、无需鉴权的本地服务和经用户明确许可的局域网 HTTP 服务都能以可预测方式配置。

**Blocked by:** 02 — 打通首个 Chat Completions 翻译闭环.

**Status:** resolved

- [x] 用户可以管理多个命名供应商配置，并且同一时刻恰有一个当前供应商配置。
- [x] 配置支持协议类型、Base URL、可选路径覆盖、可选 API Key、模型及可选额外请求头。
- [x] API Key 与额外请求头值按敏感信息加密保存，列表和编辑页不会意外展示完整秘密。
- [x] HTTPS 为默认；证书失败不会自动降级到 HTTP。
- [x] 单个配置可在明确警告后允许局域网明文 HTTP；未选择时 HTTP 请求被拒绝。
- [x] 连接测试能区分 URL、鉴权、模型和基础协议问题，并且不会写入翻译历史。
- [x] 删除当前配置后必须明确选择替代配置或进入无当前配置状态，不能静默选择未知目标。
- [x] 仓库级公开行为测试证明配置重载后仍可鉴权，同时普通存储、诊断和测试输出中不存在明文秘密。

## Answer

已在 `0.3.0` 中实现多供应商配置、显式切换、编辑、删除和连接测试。配置支持 Chat Completions、Responses 与 Anthropic Messages 三种协议的连接信息；API Key 和额外请求头值使用 Android Keystore 的 AES/GCM 加密保存，编辑页只提示已保存而不回显秘密。HTTPS 为默认；每个 HTTP 配置必须在风险警告旁明确允许，否则在网络请求前被拒绝。删除当前配置后进入“无当前供应商配置”状态，不会静默切换。

同时修复 DeepSeek 流式响应中 `content: null` 被 Android `JSONObject.optString()` 强制转换为字符串 `"null"`、从而产生 `nullnull…` 的问题；解析器现在只接受真实字符串内容，并忽略角色、推理和空内容事件。

验证证据：单元测试、Android Lint 与 debug APK 构建通过；Android API 37 模拟器上的 20 个设备测试全部通过，覆盖多配置加密重载、显式切换、当前配置删除、明文 HTTP 阻止、连接成功及 URL/鉴权/模型/协议错误分类，并在真实 Android JSON 实现上验证 DeepSeek null 回归。首次配置、列表、翻译页及秘密不回显已完成视觉验收。
